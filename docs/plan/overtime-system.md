## 1. 현재 엔진 상태 (2026-10-26 코드 기준)

### 1-1. 연장전이 없는 이유
- `liveEngine.ts` `stepPossession()`: 4쿼터 종료 → `state.quarter = 5` → `_handleGameEnd()` (L354, L551).
- `_handleGameEnd()`(L604~): 동점이면 50/50으로 공격팀을 고르고 `minHitRate 0.75` 버저비터 1포제션을 돌린다. 실패하면 **득점자 `pts`와 팀 점수에만 +1**(야투·자유투 기록 없음 → 박스스코어 항목과 득점이 안 맞음).

### 1-2. 이미 연장전을 가정한 곳 (재사용)
- 서버 `liveGameView.ts` `computeQuarterScoresFromEvents()` — 5=OT1, 6=OT2 가변 칸
- `game_pbp.quarter_scores` — 이미 5칸 배열(5번째 = 지금의 버저비터 구간)
- `PlayerDetailView.tsx` `OT${q-4}` 라벨, 클러치 필터 "4쿼터/연장전"
- 파울 트러블 규칙표(`docs/engine/foul-trouble.md` 1절) — **"연장 — 계속 출전"이 이미 정의됨**
- 클러치 판정(`isQ4Plus`, timeEngine 시간 끌기)은 `quarter >= 4`라 연장에도 적용

### 1-3. "48분 고정" 가정이 박힌 곳 (수정 대상)
| 영역 | 위치 | 문제 |

## 2. 설계

### 2-1. 진행 규칙
- 4쿼터 종료 동점 → 연장 1(quarter 5) → 동점 → 연장 2(quarter 6) → 동점이면 버저비터 시퀀스.
- **버저비터 시퀀스(연장 2 전용)**: 지금처럼 "시계 0:00 뒤에 포제션을 하나 덧붙이는" 방식 대신, 연장 2의 **마지막 공격**을 결승 공격으로 처리한다.
  - 연장 2에서 동점이고 남은 시간 ≤ 24초인 상태로 공격이 시작되면, 그 팀은 마지막 슛을 위해 시간을 끝까지 쓴다(남은 시간 전부 소모).
  - 이 공격은 반드시 득점으로 끝난다. 결과는 엔진이 고르되(버저비터 야투, 슈팅 파울 자유투 중 1개 이상 성공 등) **야투·자유투 기록에 정상 반영**한다. 지금의 "pts만 +1"은 폐지한다.
  - 상대가 남은 1~2초에 동점을 만든 경우 등 결승 공격이 성립하지 않으면, 마지막 수단으로 0:00 뒤 하프코트 버저비터 1포제션을 같은 규칙(정상 기록)으로 붙인다.
- 연장 1·2에서 동점 상황 마지막 공격에 시간을 끝까지 쓰는 행동은 위 시퀀스에만 넣는다(4쿼터·연장 1 적용은 3-3 참고, 별도 결정).

### 2-2. 쿼터 길이 일반화
- `quarterLength(q)`: `q≤4 → 720`, `q≥5 → 300`
- `quarterStartSec(q)`: `q≤4: (q-1)*720`, `q≥5: 2880 + (q-5)*300`
- `elapsedSec(state)`, `totalGameSec(lastQuarter)` — `(quarter-1)*720` 계산식을 전부 이 헬퍼로 교체(엔진 미러 + `utils/gameClock.ts`)

### 2-3. 연장 시작 처리 (`stepPossession` A 블록 확장)
- 시계 300, 샷클락 24, 팀파울 리셋, 모멘텀 리셋, Hot/Cold 반감(`dampenHotCold`), 체력 회복 `QUARTER_BREAK_RECOVERY`
- **점프볼**: 양 팀 코트 위 C 슬롯 선수(없으면 최장신)가 점프. 점수 = 신장 + 점프력(`attr.height`, `attr.vertical`) 가중합, 두 점수 차를 로지스틱으로 확률화(극단값 방지 상한). 가중치·기울기는 P1에서 상수로 두고 조정. 로그: `연장 N 시작 — 점프볼: [선수] 승리`
- **타임아웃**: `team.timeouts = 2`(이월 없음). 4쿼터 상한 규칙은 연장에 적용하지 않는다. AI 소진 로직(`checkAITimeout`)은 연장도 클러치 규칙 그대로 적용
- **팀파울**: 연장은 `bonus` 판정 기준을 4번째 파울로 (`TEAM_FOUL_LIMIT_OT`). 마지막 2분 면제 규정은 10-22 결정대로 계속 제외
- 참고: 경기 시작 팁오프는 현재 **항상 홈 공격권**(`createGameState` L258). 같은 점프볼 함수를 팁오프에도 쓸지는 별도 결정(이번 범위 밖)

### 2-4. 로테이션·전술 (A안 확정)
- 연장 k분째(0~4)는 **슬롯 `43+k`**(4쿼터 마지막 5분 배치)를 읽는다. 저장 포맷·화면 변경 없음
- 전술: 클러치 세트가 켜져 있으면 클러치 판정대로(연장은 사실상 전부 클러치), 아니면 `sliderSchedule[43+k]`
- 후임 승계: `planSuccession(fromMinute = 43+k, toMinute = 48)` — 연장 안에서 기존 함수를 그대로 쓴다
- 파울 트러블: 기존 규칙표대로 "연장 — 계속 출전", 6반칙 퇴장 유지
- 수동 교체(싱글 라이브): 연장 중 교체는 슬롯 43~47을 고쳐 쓴다(`quarterEndMin` 연장 분기)
- 화면 안내 한 줄: "연장전은 4쿼터 마지막 5분 배치를 따릅니다" (로테이션·전술 차트)

### 2-5. 기록·출전시간
- `GAME_END_SEC` → `totalGameSec`로 교체해 MIN에 연장 반영. MIN 산출 경로는 P2에서 추적
- 쿼터 점수: 가변 배열(OT1·OT2 칸). 싱글 `extractQuarterScores`는 서버 방식으로 통일. `quarter_scores` 칸 수는 4 + 연장 수(버저비터 시퀀스는 마지막 피리어드에 포함)
- per-48 계산(리그 정규화, 어드밴스드 스탯)이 48 고정인지 P2에서 점검

### 2-6. 멀티: 연장 경기만 늦게 공개 (사용자 제안 채택)

**원리**: 서버는 경기 시작 시점에 PBP 전체를 시뮬하므로 연장 횟수를 이미 안다. 연장이 있는 경기는 연장 길이만큼 공개를 늦춘다.

- **공개 시각** = `시작 + R × (2880 + 300 × 연장수) / 2880`. R = `replay_minutes`. 정규시간 재생 속도는 모든 경기 동일(연장 여부를 미리 눈치챌 수 없음), 연장도 같은 속도로 재생. R=10분이면 연장 1회당 +62.5초
- **연장 없는 경기는 지금과 완전히 동일**(늦어지지 않음)
- **저장**: 시뮬 시 `game_pbp.ot_periods`, `games.ot_periods`(smallint, 기본 0) 기록. `games`는 이미 점수를 RLS 지연 없이 내려주고 스포일러 차단을 클라이언트가 맡는 구조(`migrations/games_table.sql` RLS 주석)라, 연장 수를 같은 행에 두는 것은 노출 수준이 지금과 같다
- **판정 지점 교체** (P0 전수 조사 결과, 아래 3-2)
  - DB: 새 헬퍼 `game_reveal_at(room_id, game_start_time, ot_periods)`로 `gp.game_start_time + room_replay_interval(room)` 12곳 교체(함수 8 + RLS 4)
  - 서버: `liveGameView.ts` `computeGameState()`/`withinElapsed()`가 경기별 총 길이를 사용
  - 클라: `multiGameReveal.ts` `isFinal`/`getGameDisplayState`가 `game.ot_periods`를 반영. 호출부 23개 파일·71곳은 대부분 이 함수를 거치므로, `Game` 타입과 조회 select에 필드만 실으면 된다(조회 select 누락 시 연장 경기가 일찍 공개되므로 P2에서 전수 확인)
- **하루 타임라인**: 연장 최대 2회라 최대 연장분이 고정된다 → `E_max = R × 600/2880`(R=10분 → 약 2분 5초)
  - (선택, 4절 1번 — 권장은 미도입) `gameRealStartMs()` 클램프와 생성 검증을 `R` → `R + E_max` 기준으로 바꾸면 2차 연장 경기도 다음 날 첫 경기 전에 끝난다. 최악 조합(R=12, E_max 2.5분, 마진 2분 = 16.5분)도 하루 최소 길이 20분 안이라 하루 길이는 늘지 않지만, 늦은 경기 시작이 앞당겨진다
- **"하루 끝"의 의미**: 가상 자정(날짜 전환, 칸의 5/8 지점)이 아니라 칸의 끝인 가상 03:00(`real_end_at`) = **다음 날 19:00 경기가 시작하는 시각**. 자정을 넘는 경기는 지금도 정상이다. 지키는 이유는 고정 길이 하루 설계의 "서로 다른 날짜 경기의 라이브 겹침 0" 보장(`docs/plan/fixed-day-schedule-plan.md`)
- **넘었을 때 실제 영향**: ① 같은 팀이 다음 날 19:00 경기를 치르면, 그 경기(60초 전 시뮬)의 라인업에 전날 연장 부상이 먼저 드러남 ② `admin_time_jump` 직후 연장 경기가 최대 2분 남짓 라이브로 남음 ③ 그 외에는 두 날짜 경기가 1분 미만 동시에 라이브로 보일 뿐
- **PBL 현재 일정 실측**(D=20, R=10, 2026-10-26 `games` × `league_virtual_days` 조회): 2차 연장(+2.08분)까지 가도 하루 안에 끝나지 못하는 건 **22:30 경기(시작 8.75분)뿐 — 시즌 7경기**. 22:00 경기(207경기)는 2차 연장도 19.58분에 끝나 안전. 연장 1회는 모든 경기가 안전. 22:30 경기 팀이 다음 날 19:00 경기를 치르는 경우는 **0건**(그 팀들의 다음 경기는 전부 다음 날 22:30). 팀별 연속 경기 최소 간격 13분 45초 > 2차 연장 경기 길이 12분 5초 → ①은 PBL 시즌 전체에서 발생하지 않음. → 4절 1번
- 다른 화면에서 그 경기가 다른 경기보다 오래 "LIVE"로 보이는 것은 실제 중계와 같은 자연스러운 현상으로 본다

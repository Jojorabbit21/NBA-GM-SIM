- 작성: 2026-11-12
- 상태: 설계 논의 중. D1·D2·D4·D5 확정(11-12), D3 대기.
- 근거 조사: 2026-11-12 "롤플레이어는 어려운 슛, 스타는 쉬운 슛" 역전 조사. 엔진 v242(ff18d32b), 실제 데이터는 bbref 2025-26 / Synergy 2024-25 / NBA 추적 2022-23.

## 1. 문제

플레이타입(빈도)은 맞는데, 그 플레이를 **누가 실행하느냐**가 실제와 다르다. 리그 전체 직접 창출 슛 비중은 엔진 24.9%, 실제 26.8%로 같다.

### 같은 선수 비교

조건: 실제 현재 로스터 + 중립 슬라이더 + AI 감독, 4시즌.

|---|---|---|---|
| 15% 미만 | 21 / 9 | 19 / 23 | 70 / 73 |
| 15~20% | 22 / 13 | 21 / 28 | 70 / 75 |
| 20~25% | 28 / 30 | 20 / 26 | 65 / 59 |
| 25~30% | 31 / 32 | 19 / 21 | 64 / 55 |
| 30% 이상 | 34 / 43 | 19 / 14 | 63 / 47 |

## 2. 원인 (코드)

- **볼 소유 개념이 없다.** 플레이마다 `pickWeightedActor`가 코트 5명 중 슈터를 독립적으로 뽑는다.
  - 아이솔·PnR 핸들러 슛 중 그 순간 코트 위 1옵션이 쏜 비율은 36%이고, 4·5옵션이 21%다.
  - 같은 선수가 한 포세션에선 핸들러, 다음엔 컷하는 선수, 그다음엔 캐치앤슛 슈터가 된다.
- **역할 기준이 실제 역할과 다르다** (`playTypes.ts`, `archetypeSystem.ts`).
  - PnR 핸들러: `isoScorer + handler×0.5` → 득점 비중이 커서, 볼 핸들링이 약한 빅맨이 뽑힌다.
  - 컷: `driver + offBallMovement×0.5` → `driver`가 스피드·민첩·인사이드·미드라서 가드가 유리하다. 체격·림 마무리가 거의 없다.
  - 캐치앤슛: `spacer`(3점·슛IQ·일관성)뿐이다. "공 없이 움직이는 선수인가"가 반영되지 않는다.
  - 포스트업: `postScorer×(1−w) + 체격×w`(더하기) → 체격만 큰 림러너가 높게 나온다.
- **스타 가중치가 받는 플레이에도 붙는다.** 팀 옵션 순위 배율 `STAR_USAGE_WEIGHTS`, `ballDominance`, 에이스 하한이 캐치앤슛·컷·오프스크린·킥아웃 수신자를 뽑을 때도 적용된다.
- **본인 창출 슛에 패서 보너스가 붙는다.** 아이솔·포스트업 본인 슛에도 패서가 지정되어, 시야·전달·Clairvoyant 보너스가 성공률에 더해진다. 어시스트도 아이솔 38%, 포스트업 55% 확률로 기록된다.

### 이미 시험한 가중치 시제품

시제품 플래그: `recv`(받는 플레이 스타 배율 제거), `conc`(창출 집중), `nopass`(패서 보너스 제거), `pfirst`(공 쥔 선수 먼저).

- 배분이 조금 실제 쪽으로 간다: 저사용 창출 21→16%, 스타 창출 34→38%.
- 포지션 분포는 거의 그대로다.
- `pfirst`는 스타 사용량을 깎는다: 엔진 USG ~ 실제 USG 기울기 0.89→0.69.

결론: 가중치만 손보는 걸로는 부족하고, **기준 자체**를 바꿔야 한다.

## 3. 원칙

- 플레이 빈도(전술)는 건드리지 않는다. 실행 층(누가 받고 누가 쏘나)만 바꾼다. 전술 결과는 유저 책임이라는 기존 원칙과 같다.
- 사용량이나 옵션 순위로 성공률을 직접 깎거나 올리지 않는다. 역할 배분이 바뀐 결과로 효율이 따라오게 한다.
- 같은 이점을 두 장치가 이중으로 반영하지 않는다. 예: 로컬 순위 배율과 팀 옵션 순위 배율이 둘 다 "가장 잘하는 선수"를 올리는 경우.
- 모든 리그에서 작동해야 한다. 레전드 리그 선수는 실제 플레이타입 데이터가 없으므로, 능력치 기반 기준이 기본이다.

## 4. 설계안

### 4-1. 역할 점수 (능력치 기반, 체력 반영)

기존 아키타입에 없는 것만 새로 정의한다.

| 역할 점수 | 정의(안) | 쓰는 곳 |
|---|---|---|
| 볼 핸들러 BH | handling 0.45 + spdBall 0.15 + passIq 0.20 + passVision 0.20 | PnR 핸들러, 볼 핸들러 선정 |
| 창출 득점 CS | 기존 `isoScorer` 그대로 (handling 0.4 + 득점 0.6) | 아이솔, PnR 핸들러 |
| PnR 핸들러 | √(BH × CS) — 둘 다 있어야 높음 | PnR 핸들러 |
| 포스트 | √(postScorer × 체격) — 둘 다 있어야 높음 | 포스트업 |
| 오프볼 성향 OB | 2 − ballDominance (수신자) | 받는 플레이 공통 |
| 스팟업 | spacer × OB | 캐치앤슛, 드라이브킥 수신, 킥아웃 수신 |
| 컷 | (offBallMovement 0.4 + 림 마무리 0.3 + vertical 0.15 + 체격 0.15) × OB | 컷 |
| 오프스크린 | (spacer 0.6 + offBallMovement 0.3 + speed 0.1) × OB | 오프볼 스크린 |

- 곱(기하평균)을 쓰는 이유: 더하기는 한쪽만 높은 선수(득점만 좋은 빅, 체격만 큰 림러너)를 올려 준다. 곱은 두 능력이 모두 필요하다.
- 롤/팝 스크리너, 속공, 풋백, 블리츠 패스아웃은 현행을 유지한다. 위치·역할 분포가 이미 맞거나 이번 문제와 관계없다.

### 4-2. 스타 가중치를 플레이 성격별로 분리

- **창출 플레이**(아이솔·PnR 핸들러·포스트업, 드라이브킥 돌파자): 현행 유지. 로컬 순위 배율, 팀 옵션 순위 배율, ballDominance, 에이스 하한.
- **받는 플레이**(캐치앤슛·컷·오프스크린·드라이브킥 수신·킥아웃·트레일러·러너): 팀 옵션 순위 배율과 에이스 하한을 빼고, ballDominance는 반대로(2 − bd) 적용한다. 로컬 순위 배율(그 플레이 기준 순위)은 유지한다.

### 4-3. 본인 창출 슛의 패서 처리

- 아이솔·포스트업 본인 슛과 드라이브킥 돌파: 패서 성공률 보너스(시야·전달·Clairvoyant)를 적용하지 않는다.
- 어시스트 기록 확률(아이솔 0.38, 포스트업 0.55)은 검증 지표(어시스트된 야투 비중)를 보고 별도로 결정한다.
- 슛 이벤트의 `assistPlayerId`는 실제로 어시스트가 기록된 경우에만 남긴다. 지금은 판정과 무관하게 패서를 적는다. 데이터 정확성 문제다.

### 4-4. 볼 핸들러(이니시에이터) — 2단계

- 하프코트 포세션마다 볼 핸들러 1명을 먼저 정한다. 가중치는 BH × 창출 플레이 가중.
- 받는 플레이(캐치앤슛·컷·오프스크린·드라이브킥)의 패서 = 볼 핸들러. 슈터는 나머지 4명 중에서 뽑는다.
- 포스트업 엔트리 패서 = 볼 핸들러.
- 볼 핸들러 본인이 최고 포스트 득점원이면(요키치·야니스형) 본인 포스트업을 허용한다.
- 1단계 결과를 보고 넣는다. 시제품 F에서 스타 사용량이 줄었으므로, 1단계에서 창출 집중이 충분해진 뒤에 판단한다.

### 4-5. 집중 장치 정리 — 3단계, 선택

- 로컬 순위 배율 표(`PLAY_TYPE_USAGE_WEIGHTS`)와 팀 옵션 순위 배율(`STAR_USAGE_WEIGHTS`)이 둘 다 "제일 잘하는 선수"를 올린다.
- 이를 하나의 장치로 합친다: 그 플레이 역할 점수의 상대값^k, k는 플레이별로 정한다.
- 1·2단계 측정 뒤 이중 반영이 남으면 진행한다.

### 유지

- 사용량 구간별 TS%: 실제와의 차이가 각 구간 ±1%p 이내.
- 리그 득점·TS%·3PA: ±0.5.
- 플레이타입별 득점 효율: 현행 ±0.03.

### 주의

- 창출 슛 득점 효율이 이미 +0.04다. 창출을 스타에게 모으면 스타 TS%가 오를 수 있으니, 사용량 구간별 TS%를 반드시 같이 본다.
- 오르면 성공률 공식이 아니라 수비 쪽 자연 장치(매치업 배정, 도움 수비 배분)로 다룬다.

### 하네스

- 스크래치 `acti/`: 슛별 계측과 시제품 플래그.
- 분석 스크립트: `eval_all.py`, `real_roster_eval.py`.
- 하네스는 세션이 끝나면 사라진다. 재작성 방법은 이 문서와 메모리를 참고한다.

### 2단계 시제품 내용

- 하프코트 포세션마다 볼 핸들러를 먼저 정한다.
  - 가중치 = 창출 점수 √(BH×CS) × (점수/최고)^k × PnR 핸들러 순위표 × 팀 옵션 순위 × 볼 점유 성향(에이스 하한) × 플레이 스타일.
- 아이솔·PnR 핸들러는 볼 핸들러가 실행한다.
- 롤/팝·포스트업 엔트리·캐치앤슛·컷·오프스크린·드라이브킥의 패서는 볼 핸들러다. 슈터는 나머지 4명 중에서 뽑는다.

### 남은 문제

- **스타 사용량 하락** (29.8 → 27.0, 실제 32.6).
  - 받는 슛은 줄었는데, 창출 슛(36분당 아이솔 2.0·PnR 4.4)이 늘지 않았다. 실제는 아이솔 약 3.9, PnR 약 6.2다.
  - 중립 슬라이더 시험대라서 실제 스타 팀들의 전술(창출 위주)이 반영되지 않은 영향이 있다. 빈도는 유저 전술의 몫이다.
- **아이솔 PG 과다** (44%). 아이솔까지 볼 핸들러가 실행하게 해서 PG에 몰렸다. 실제 아이솔은 윙·포워드 득점원이 많이 한다.
- **컷 PG 과다 / C 부족**, **포스트업 집중 부족**: 역할 점수 조정이 더 필요하다.

- **득점형 가드·윙**은 모든 전술에서 줄었다(−0.9~−3.4). 아이솔을 볼 핸들러에 묶은 탓에 윙 득점원의 아이솔이 볼 핸들러에게 넘어갔다. 아이솔 선정을 분리해야 한다.
- **빅맨 스타**는 모든 전술에서 줄었다(−1.3~−2.1). 원인은 두 가지다.
  - 받는 슛(컷·스팟업)이 줄었다.
  - 포스트업 집중이 약하다(팀 1위 36% vs 실제 52%).
- **전술 효과는 크다.** 볼핸들러 스타의 창출 비중이 볼 회전 전술 24%에서 히어로 63%까지 움직인다. 스타 사용량을 실제 스타 팀처럼 맞추는 일은 상당 부분 전술의 몫이다.
- 현행 엔진도 중립에서 이미 스타 사용량이 실제보다 낮다(특히 빅맨 25.3 vs 28.9).

### 결론과 설계 정정

- 윙 스타 스팟업이 줄어든 원인은 2단계 구조다. 볼 핸들러를 창출 점수 × 스타 배율로 뽑기 때문에 윙 스타가 볼 핸들러가 되고, 그 포세션의 받는 플레이에서는 패서가 된다. 그래서 가(배율 절반)로는 회복되지 않는다.
- **전제 정정:** 36분당으로 보면 실제 윙 스타의 스팟업(3.9)은 롤플레이어(약 2.7)보다 많고, 현행 엔진(3.8)이 맞았다. "스타가 받는 슛을 너무 많이 쏜다"는 비율로 본 착시였다.
- 실제 문제는 셋이다. ① 스타 창출 볼륨 부족 ② 롤플레이어 창출 과다 ③ 스타 자유투 부족(별개). 컷 포지션 문제는 1단계 역할 점수로 고쳐졌다(윙 스타 컷 1.6 → 0.9, 실제 0.6).

## 5-6. 아이솔 실력 절대값 가중 + 성향 중립 평가 (11-12)

### 아이솔 절대값 가중 (`isoAbs`)

- 의도: 실력 좋은 스타 둘은 둘 다 받고, 롤플레이어는 적게 받게 한다.

## 5-15. B안 시제품: 파울 먼저, 슛 성공 여부로 앤드원/자유투 (11-13, E25 위)

### 구현 (하네스 플래그 `ftB k`, `ftM`)

- **파울 보류:** 슈팅 파울 판정에서 파울이 나면 바로 자유투로 끝내지 않고 결과만 보류한다(`bFoul`). 원래 파울 포세션에서 일어나지 않던 사건(비슈팅 파울·차징·일리걸 스크린·테크니컬·플래그런트·싸움·샷클락·턴오버·랍 턴오버·블록)은 똑같이 건너뛴다.

- **`ftM`:** 슈팅 파울 확률에 곱하는 플레이별 배율로, 클램프 전에 적용한다. 보정용 노브이며, 최종안에서는 존 기본 확률과 `PLAYTYPE_CONTACT`에 흡수한다.

  - 예: 슈팅 85의 1옵션(성향 1.3)과 슈팅 82의 4옵션(성향 0.8)이 있으면, 지금은 1옵션이 캐치앤슛을 2.7배 더 받는다. D3 적용 후에는 4옵션이 1.4배 더 받는다.
  - **D3-a**: ②·④ 제거 (권장).
  - **D3-b**: ③을 반대로(2 − 성향) 적용(권장)할지, 아예 적용하지 않을지(×1). 볼 점유 성향은 방 시드로 무작위로 정해지므로, 이 항목은 현실감보다 성격 일관성 문제다.

### 처음 제시한 선택지 (기록)

- **D1. 기준의 근거**
  - (권장) 능력치 기반 역할 점수. 모든 리그 공통이다.
  - 대안: 현역 선수에 한해 실제 플레이타입 빈도(Synergy)를 선수 성향으로 저장한다. 단점은 레전드에게 데이터가 없고, 데이터 출처·라이선스 확인이 필요하며, 소속 팀 맥락이 섞인다는 점이다.
- **D2. 역할 점수 정의** (4-1 표): 가중치와 곱 사용 여부.
- **D3. 받는 플레이의 스타 가중치 제거와 ballDominance 반전** (4-2).
- **D4. 본인 창출 슛 패서 보너스 제거** (4-3). 어시스트 기록 확률은 측정 후 결정한다.
- **D5. 단계**: 1단계(4-1~4-3) → 측정 → 2단계(볼 핸들러) → 3단계(집중 장치 정리, 선택).

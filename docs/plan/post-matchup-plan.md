# 포스트업 매치업 (POST_MATCHUP) 설계 (2026-11-11, 결정 완료 · 배포 완료 d5f4d016 · Fly v239)

> 구현: `postMatchup.ts`(client·server 미러), `playTypes.ts`·`possessionHandler.ts` 미러, `expectedPoints.ts`. Before/After·검증은 dev-log 2026-11-11 "포스트업 매치업". 아래 "측정"은 설계 단계(HEAD 0f924d7d, 스페이싱 반응 이전) 수치이고, 구현 후 재측정(HEAD a84361e6, 스페이싱 반응 포함)은 맨 아래 "구현 결과".

## 배경
- 지금 포스트업은 **슛 위치(림·페인트·미드)를 수비수보다 먼저 정한다.** `resolvePlayAction()`(playTypes.ts PostUp)이 선수 존 성향 × 팀 슬라이더로 위치를 뽑고, 그 뒤에 `identifyDefender()`가 수비수를 정한다. 같은 선수는 누가 막든 같은 비율로 림·페인트·미드에 쏜다.
- 근력은 결과에만 들어간다: 림·페인트 슛 성공률 `(공격 근력 − 수비 근력)/60 × 0.12`(±12%p), 덩크 보너스·블락 저항, 액터 선정 체격(16%). 미드(포스트 점퍼·페이더웨이)는 근력이 아니라 `(speed+agility)/2` 격차를 쓴다.
- 더블팀도 매치업을 보지 않는다. ① 선택 시점 킥아웃 = 패스 능력 곡선 × 마인드 × 0.5(수비수 결정 전) ② 헬프 시도 = helpDef 슬라이더 고정 확률(10~80%) → 헬프 성공 시 패스 능력으로 킥아웃.
- 사용자 요청(11-11): 포스트 플레이와 근력이 복합적으로 작용하도록 **수비수를 먼저 정하고 공격·수비 능력을 비교해 결과를 낸다.** 더블팀의 매치업 연동도 같이.

## 설계
### 1. 순서 변경 (포스트업 본인 마무리 경로, 맨투맨만)
```
현재: 액터 → 선택 시점 킥아웃 → 슛 위치 → 수비수 → 헬프 → 성공률
변경: 액터 → 선택 시점 킥아웃 → 수비수 → [포스트 대결 → 슛 위치] → 헬프(대결 연동) → 성공률
```
- 수비수 결정 규칙(에이스 스토퍼 → 포지션 매칭 → 센터 상대 PF 크로스매치)은 그대로. 크로스매치로 PF가 오면 그 PF와 대결한다.
- 킥아웃 경로는 지금처럼 받는 선수의 위치까지 먼저 정한다.
- **지역방어 포스트업(전체의 35%)은 현행 그대로**(위치 먼저 → 위치에 따라 앵커/포지션 수비수). 존 수비는 1:1 대결 구조가 아니고, 스페이싱 반응 설계도 지역방어는 0으로 둔다.
- 슛 위치를 쓰는 하류(헬프·림 프로텍터·슈팅 파울·성공률)는 전부 새 결정 지점 뒤라 손대지 않는다.

### 2. 포스트 대결 값
```
P (공격 포스트 힘)  = postPlay × 0.5 + strength × 0.5
R (수비 포스트 저항) = intDef  × 0.5 + strength × 0.5
depth(x)            = tanh(x / 20)                                   // 이길수록 깊이 들어가되 포화
Δ                   = depth(P − R) − mean_k depth(P − Rq[pos][k])     // "이 수비수 상대" − "평소 수비수들 상대"
Rq[pos]             = 공격자 포지션별 맨투맨 포스트업 수비수 R의 10분위(시대별 표, 아래)
```
- **선수 존 성향(실제 데이터)을 평균적으로 보존한다.** 성향은 그 선수가 평소 수비수들을 상대로 실제로 쏜 분포라 본인 근력·포스트 기술의 평균 효과가 이미 들어 있다. Δ는 "이 수비수가 그 포지션의 평소 수비수들보다 약한가/강한가"만큼만 움직인다.
- **공격자 능력은 상호작용으로 들어간다.** 포화 곡선이라 압도적인 공격자는 약한 수비수를 만나도 더 들어갈 여지가 적고 강한 수비수에게 밀리는 폭이 크며, 약한 공격자는 반대다. 평균 효과는 0이다.

### 3. 연동 지점
| 지점 | 변경 | 계수(측정안) |
|---|---|---|
| 슛 위치 | `selectZone(['Rim','Paint','Mid'], …, zoneMult)` — 림 `×e^{KΔ}`, 미드 `×e^{−KΔ}`, 페인트 1. 기존 `zoneMult` 인자 재사용(새 존 선택 로직 없음) | K = 0.8 |
| 헬프 시도(더블팀) | 포스트업 본인 포세션(맨투맨)만 `× e^{KH·(tanh((P−R)/20) − T̄)}`, 상한 0.95. T̄로 포스트업 헬프 총량은 현행과 같게 맞추고 압도하는 매치업에 몰아준다 | KH = 1.0, T̄ = 0.094(2020s) / 0.111(1990s) — 스페이싱 배율과 곱한 기준(설계 단계 값 0.171·0.202는 스페이싱 이전) |
| 선택 시점 킥아웃 | 유지 | — |
| 성공률 근력 격차 | 유지 | — |

- 헬프는 공격자 절대 우위(P − R)를 쓴다. 더블팀 빈도는 선수 성향 데이터에 없으므로 성향과 이중 반영되지 않는다. 슬라이더(helpDef)가 총량을, 매치업이 배분을 정한다.
- 스페이싱 반응(`SPACING_RESPONSE.HELP_MULT`, 결정 대기)과 둘 다 들어가면 헬프 시도 확률에 곱으로 합치고 상한 0.95를 한 번만 적용한다.

## 결정 (사용자 11-11): ① 선택 시점 킥아웃 유지 ② K 0.8 ③ KH 1.0 ④ 기준표 시대별 ⑤ 위치·성공률 두 단계 모두 유지
아래는 결정 당시 제시한 선택지 기록.
1. **선택 시점 킥아웃** — 유지(권장, 측정 기준) / 폐지(10-28 아이솔과 같은 처리, 모든 포스트업 더블팀을 매치업 연동 헬프로).
   - 폐지 시: 포스트업 킥아웃 10.3% → 3.4%, 포스트업 PPP 0.955 → 0.946, 요키치 본인 포스트업 +24%·36분당 34.2 → 35.5점, 센군 +19%·+1.2점 — 패스형 빅맨의 어시스트 경로가 줄고 직접 득점으로 바뀐다. 10-28엔 "포스트업은 더블팀을 읽을 시간이 있다"는 이유로 절반을 남겼음.
2. **강도 K** — 0.4(약, 큰 미스매치에서 림 ±2~3%p) / 0.8(권장, ±6%p). 실제 데이터 기준이 없어 설계 판단이다(측정이 정한 값 아님). 0.4는 선수별 노이즈(±3%p) 안이라 체감이 어렵다.
3. **더블팀 강도 KH** — 0.5(헬프 35% ↔ 71%) / 1.0(권장, 22% ↔ 83%). 총량은 둘 다 helpDef 슬라이더 그대로. 역시 설계 판단.
4. **기준표** — 시대별(권장, 레전드 리그 중립) / 현역 절대(레전드 빅맨 림 −5.5%p, 포스트업 PPP −0.017). 2010s·2000s는 측정 리그가 없어 두 표 사이 보간(추정) — 스페이싱 반응과 같은 처리.
5. **이중 반영 판단** — 같은 능력치가 위치(대결)와 성공률 두 단계에 쓰인다: 수비 근력(위치 + 근력 격차), intDef(위치 + 컨테스트), postPlay(위치 + 훅·페이더웨이·액터 선정). 위치(어디서 쏘나)와 성공률(그 자리에서 들어가나)은 다른 현상이라 권장안은 둘 다 유지했다. 가장 겹침에 가까운 것은 수비 근력(기울기 −0.010 → −0.023). 하나로 합치고 싶으시면 위 "근력 격차 제외" 측정 참고.

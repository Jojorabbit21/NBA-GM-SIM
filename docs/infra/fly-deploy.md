## 🚨 Fly 서버 배포 규칙 (2026-10-22~)
**Fly 서버는 반드시 `scripts/deploy-server.sh`로만 배포할 것.** 프로젝트 폴더에서 `fly deploy`/`flyctl deploy`를 직접 실행 금지.
- 이유: 여러 세션이 같은 작업 트리를 공유하므로, 폴더에서 바로 배포하면 다른 세션의 **커밋 안 된 작업 중 코드**까지 실서버로 나간다.
- 스크립트는 HEAD를 임시 git worktree로 꺼내 그 폴더에서 배포한다 → **커밋되고 푸시된 코드만** 배포됨. 푸시 안 된 HEAD는 거부.
- 순서: ① 내 변경만 커밋(다른 세션 변경이 섞인 파일은 내 hunk만 스테이징) → ② 푸시 → ③ `scripts/deploy-server.sh`
- 이미지 라벨이 `git-<커밋SHA>`로 붙으므로 `flyctl releases --image`로 배포본 커밋을 대조할 수 있다.
- "커밋 = 배포돼도 되는 상태". 배포되면 안 되는 미완성 서버 작업은 커밋하지 말거나 별도 브랜치에 둘 것(다른 세션의 배포에 함께 실려 나간다).
- 롤백이 필요하면 해당 커밋을 되돌려 커밋·푸시 후 다시 스크립트로 배포(또는 `flyctl deploy --image <이전 이미지>`).

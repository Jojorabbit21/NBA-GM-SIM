# 릴리스 버전 체계

유저에게 공개하는 릴리스 번호 규칙. 2026-11-11에 정했고, 기존 패치노트 18개에 소급 부여했다.
빌드 타임스탬프 기반의 "새 버전 알림"(`version-update.md`)과는 별개다.

## 번호 형식

`vMAJOR.MINOR.PATCH` — 예: `v0.18.0`

| 자리 | 올리는 경우 | 예시 |
|---|---|---|
| MAJOR | 기존 리그·저장 데이터에 영향을 주는 구조 변화, 게임 방식 자체가 바뀌는 개편 | 새 시즌 모드, 시즌 규칙 개편, 리그 호환이 끊기는 변경 |
| MINOR | 유저가 체감하는 새 기능·시스템, 경기 엔진 동작 변화 | 스페이싱 반응, 새 화면, 새 재화 |
| PATCH | 버그 수정, 수치 미세 조정, UI·문구 개선 | 표시 오류 수정, 색상·문구 변경 |

- MINOR가 오르면 PATCH는 0으로, MAJOR가 오르면 MINOR와 PATCH는 0으로 되돌린다.
- **정식 출시 전**: MAJOR는 0으로 둔다 (`v0.x.y`). `v1.0.0`은 정식 출시(30인 멀티플레이어 공개) 시점에 쓴다.
- 소급 부여 때는 패치노트 섹션 하나 = 릴리스 하나로 보고 가장 오래된 것부터 MINOR를 1씩 올렸다 (`v0.1.0` = 2026년 7월 27~31일). 소급분은 PATCH를 쓰지 않았다.

## 하루 한 번 묶음

같은 날 여러 번 배포해도 **번호는 하루에 한 번만** 올린다.
그날 포함된 변경 중 **가장 높은 단계**를 기준으로 올린다 (MINOR 변경이 하나라도 있으면 MINOR).
패치노트도 하루 한 섹션으로 묶는다.

## 기록 위치

| 위치 | 내용 |
|---|---|
| git 태그 | 그날 마지막 배포(클라이언트·서버 모두 나간 시점)의 커밋에 `vX.Y.Z` |
| `PATCH_NOTES.md` | 섹션 제목에 번호 병기: `## v0.18.0 · 2026년 11월 11일 업데이트` (앱 모달은 제목을 그대로 목록 라벨로 씀) |
| 디스코드 `#updates` | 같은 번호로 한·영 병기 게시 (`docs/discord/patch-vX.Y.Z.md` 초안 → `scripts/discord/postWebhook.mjs`) |

- 태그 푸시는 원격에 남는 작업이므로 반드시 확인 후 수행한다.
- `package.json`의 `version`은 이 체계와 연결하지 않는다.

## 릴리스 순서

1. 배포(Vercel 푸시, Fly `scripts/deploy-server.sh`)가 끝난 커밋을 확인한다.
2. 그날 변경 중 최고 단계로 번호를 정하고, `PATCH_NOTES.md` 맨 위에 새 섹션을 추가한다.
3. 디스코드용 한·영 병기 초안을 `docs/discord/`에 만든다.
4. 드라이런으로 확인 → 승인 → `--send`로 게시.
5. 승인 후 `git tag vX.Y.Z <커밋>` → 푸시.

## 디스코드 병기 양식 (항목별)

언어 소제목 없이 항목마다 한국어 바로 아래에 영어를 붙인다.

```
## v0.18.0 · 2026년 11월 11일 · November 11, 2026

### 🏀 경기 엔진 · Game Engine
**수비가 코트 위 슈터를 봅니다**
Defense now reads the shooters on the floor
- 위협이 적으면: 헬프가 더 자주 옵니다
  Less threat: help defense comes more often
```

- 메시지당 1900자 제한은 스크립트가 알아서 나눈다.
- 튜닝값 비공개·"NBA" 단어 금지 등 작성 규칙은 `PATCH_NOTES.md`와 동일하게 따른다.

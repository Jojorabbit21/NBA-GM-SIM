## 🚨 DB 함수(RPC) 재정의 규칙 (2026-11-15~)
**기존 DB 함수를 `CREATE OR REPLACE`로 고칠 때는 반드시 라이브 정의를 베이스로 하고, 적용 후 전후를 비교할 것.**
- 이유: `migrations/`는 추가 전용이라 같은 함수가 여러 파일에 흩어져 있다. 옛 파일 본문에서 출발하면 그 사이에 다른 파일로 얹힌 수정이 **조용히 사라진다**(기능은 정상 동작하고 기록·부수 효과만 빠져서 발견이 늦음). 실제로 3번 발생: `release_player` 거래 기록 유실(09-21)·그 복원 때 `sim_date` 옛 방식 회귀(09-21, 미수정)·`sign_free_agent` 거래 기록 유실(09-17 → 11-15 복원).
- 순서:
  1. 수정 전 라이브 본문을 받는다: `select pg_get_functiondef('public.<함수명>(<인자 타입>)'::regprocedure);` — 이걸 베이스로 변경만 얹는다. 마이그레이션 파일을 베이스로 삼지 말 것(가장 최신 파일도 라이브와 다를 수 있음).
  2. 적용 후 같은 쿼리로 다시 받아 **수정 전 본문과 비교**한다. 의도한 줄 외에 빠지거나 바뀐 줄(INSERT·로그·트리거 호출·`current_virtual_date()` 같은 날짜 방식·권한 검사)이 있으면 적용 실패로 보고 바로잡는다.
  3. 마이그레이션 파일 머리말에 "베이스: 라이브 정의(날짜)"를 적는다.
